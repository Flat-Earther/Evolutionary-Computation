# Evolutionary Computation

Solutions and experiments developed for the **Evolutionary Computation** course at **Poznań University of Technology**.

The project focuses on solving a combinatorial optimization problem in which a subset of nodes must be selected and arranged into a Hamiltonian cycle while minimizing both the cycle length and the costs of the selected nodes.

## Problem

We are given a set of nodes represented by:

* `x` coordinate
* `y` coordinate
* node selection cost

The goal is to select exactly **50% of the nodes**, rounded up when the number of nodes is odd, and construct a **Hamiltonian cycle** through the selected nodes.

The objective is to minimize:

```text
objective = total cycle length + total cost of selected nodes
```

Distances between nodes are calculated using the Euclidean distance and mathematically rounded to integer values.

The distance matrix is calculated immediately after reading an instance. Optimization algorithms operate only on the **distance matrix and node costs**, without accessing the original node coordinates. This makes the optimization methods independent of the input representation.

More detailed information about the problem can be found in [`problem-description/`](problem-description/).

# Lab 01 — Greedy Heuristics

The first laboratory investigates several greedy approaches to the node-selection and Hamiltonian-cycle problem.

### Implemented methods

1. **Random solution**
2. **Nearest neighbor — append only**
3. **Nearest neighbor — arbitrary insertion**
4. **Greedy cycle**

Despite the name *nearest neighbor*, the next move is **not selected based solely on geometric distance**. Every candidate change is evaluated using its effect on the complete objective function, including both:

* change in cycle length
* cost of the selected nodes

The best change according to the objective function is selected.

### Random solution

A solution is generated by randomly selecting the required number of nodes and arranging them into a cycle.

For the experiment, **200 random solutions** are generated.

### Nearest neighbor — append only

Starting from a given node, nodes are iteratively added to the **end of the current path**.

For every step, the candidate node producing the best objective value is selected.

The experiment generates **200 solutions starting from each node**.

### Nearest neighbor — arbitrary insertion

Starting from a given node, a new node may be inserted:

* at the beginning,
* at the end,
* or between any two nodes already present in the path.

All possible insertions are evaluated according to their effect on the objective function, and the best one is selected.

The experiment generates **200 solutions starting from each node**.

### Greedy cycle

A greedy cycle is constructed by selecting changes that provide the best improvement of the objective function while maintaining a valid solution containing the required number of nodes.

The experiment generates **200 solutions starting from each node**.

# Lab 02 — Greedy Regret Heuristics

The second laboratory extends the constructive methods from lab 01 with regret-based candidate selection. The new methods are tested with both insertion representations used previously:

* **Extended nearest neighbor** — an open path where insertion is evaluated at the beginning, end, and every internal path position.
* **Greedy cycle** — a closed cycle where insertion is evaluated on every current cycle edge.

### Implemented methods

1. **Greedy 2-regret heuristic**
2. **Greedy weighted-sum heuristic**

Each method is implemented in both forms, producing four evaluated variants: 2-regret path, 2-regret cycle, weighted regret path, and weighted regret cycle.

### Greedy 2-regret heuristic

For every unused node, all valid insertion positions are evaluated using the change in the objective function. Let `best_delta` and `second_delta` be the two smallest changes for a candidate node. Its regret value is:

```text
regret = second_delta - best_delta
```

The node with the largest regret is selected and inserted at its best position. A large regret means that postponing the node may force a substantially worse insertion later.

For the path version, the construction starts from a selected node and keeps an open path until the required number of nodes is reached. For the cycle version, the construction starts with two nodes and maintains a closed cycle during insertion.

The experiment generates **200 solutions starting from each node**.

### Greedy weighted-sum heuristic

The weighted method combines the regret value with the best immediate change of the objective function:

```text
score = regret_weight * regret - delta_weight * best_delta
```

The candidate with the largest score is selected. The default experiment uses equal weights (`regret_weight = 1`, `delta_weight = 1`), but other values can be tested from the command line. The experiment also generates **200 solutions starting from each node**.

### Comparison with Lab 01

The Lab 02 executable contains only the four regret-based variants described above. The Lab 01 methods are not duplicated in the Lab 02 source code or rerun by its executable.

For direct comparison, the Lab 02 report generator imports the Lab 01 baseline statistics, runtimes, routes, and visualisation artifacts from:

```text
lab-01-greedy-heuristics/evaluation/
```

The report therefore compares the new regret methods with the earlier heuristics without duplicating their implementation.

## Lab 02 Evaluation

For every problem instance and every Lab 02 regret method, the experiment reports:

* **Minimum** objective value
* **Maximum** objective value
* **Average** objective value
* **Standard deviation**
* **Total construction time**

Additionally, the best and worst solutions found by each Lab 02 method are saved as node-index lists and visualized in **2D**. Node costs are represented using node colour and size. The report uses the corresponding Lab 01 evaluation artifacts for the baseline comparison rows.

The supplied instances contain 200 nodes, so each Lab 02 method generates 200 solutions from the possible starting nodes. The default run generates 1,600 routes in total (800 per instance). Every route is internally validated for exactly 100 distinct selected nodes, valid zero-based indices, and a repeated first node closing the cycle. The saved route objectives are also independently recomputed from the instance data.

The evaluation results and generated data are stored in:

```text
lab-02-greedy-regret-heuristics/evaluation/   # regret-method artifacts
lab-01-greedy-heuristics/evaluation/           # imported baseline artifacts
```

The complete analysis, visualizations, results, and conclusions are included in:

```text
lab-02-greedy-regret-heuristics/report.pdf
```
